# 快捷指令「续保导入」搭建步骤

开发者在自己的 iPhone 上照下面手工搭一次，分享出 iCloud 链接，填进 `skills/xubao/导入手机.md` 与根 `README.md`；之后律师都是点链接一键安装。Windows 上程序生成的 `.shortcut` 未经 Apple 签名，iOS 15 起导入不了；借 Mac 用 `shortcuts sign` 签名可以免手搭，但要一台 Mac，现在选了手搭。导入文本的格式以 `skills/xubao/FORMAT.md` 为准；格式号变了，这里与快捷指令一起改，重新分享链接。

## 免手搭：生成并签名

`python scripts/build-shortcut.py --hubsign` 生成快捷指令并交 HubSign 远程签名（借用 Cherri 编译器的标识，开发者知情后的决定；手边有 Mac 时改用 `--sign`），签好的文件在 `.scratch/续保导入.shortcut`。传到 iPhone 上用「文件」打开，点「添加快捷指令」，再照下面「试跑」走一遍、填验证表。生成的动作与下面手搭的步骤有三处不同：查重是先找出标题以「续保｜」开头的全部提醒、逐条读备注最后一行比对识别码（查找提醒事项能过滤的属性里没有备注）；一批识别码命中的条数少于响铃点数时当作上次没导完的半截批，删掉重建；剪贴板里不是导入文本就提示，不走扫码（iOS 27 起「扫描二维码」改成扫图片）。下面的手搭步骤留作生成件导不进或跑不通时的后备。

**不要用「父提醒事项」把响铃点挂成子任务**：iOS 26.5 上能建，26.6.1、26.6.2 上报「添加新提醒事项失败，因为提醒事项账户 iCloud 不支持子任务」，账户已升级、手动能建子任务也一样。一批平铺几条。

## 手搭

动作名按 iOS 中文界面写，**尚未在真机上核过**，个别名字在 iOS 26 上可能不同；找不到就在动作搜索框里输关键词（「提醒」「词典」「剪贴板」）。搭的时候顺手做末尾的验证，结果填进那张表。

## 准备

1. 「提醒事项」App 里新建列表「续保」。
2. 「快捷指令」App 右上角 ＋ 新建，名字改成「续保导入」。

## 动作（从上往下加）

### A. 拿到导入文本

1. **获取剪贴板**。
2. **如果**「剪贴板」**不包含** `"format"`（带英文双引号）：
   - **扫描二维码或条形码**，再 **设定变量** `原文` 为「扫描结果」。日后的二维码导入走这条；现在点快捷指令时见到相机，就是剪贴板里没有导入文本。
   - **否则**：**设定变量** `原文` 为「剪贴板」。

### B. 解析，守格式号

3. **从输入中获取词典**，输入 `原文`。
4. **获取词典值**，键 `format`。
5. **如果**「词典值」**不是** `2`：**显示提醒**「请更新快捷指令」，**停止此快捷指令**。不要往下猜着建。

### C. 先删作废的旧提醒

6. **获取词典值**，键 `void`，词典选第 3 步的「词典」。
7. **重复每一项**（对象是上一步的结果），循环里：
   - **查找提醒事项**，过滤：「列表」是「续保」；「备注」包含「重复项目」。**不加**「已完成」过滤，已完成的也要算。
   - **删除提醒事项**（有的版本叫「移除提醒事项」），对象是「提醒事项」。

### D. 逐批新建

8. **获取词典值**，键 `batches`，词典选第 3 步的「词典」。
9. **重复每一项**（对象是上一步的结果），外层循环里依次：
   1. **设定变量** `批` 为「重复项目」。**这一步必须有**：进了内层循环，「重复项目」就指内层那一项了。
   2. 四次 **获取词典值**（词典都选 `批`），键分别是 `id`、`title`、`notes`、`alerts`，各接一个 **设定变量**：`识别码`、`标题`、`备注`、`时点`。
   3. **查找提醒事项**，过滤：「列表」是「续保」，「备注」包含 `识别码`。**不加**「已完成」过滤。接 **计数**（项目），得已有几条。
   4. **计数**（项目）`时点`，得这批几个响铃点。**计算**：响铃点数减已有条数。
   5. **如果**「计算结果」**大于** 0（没导过，或上次没导完）：
      - **如果** 已有条数 **不是** 0：**删除提醒事项**，对象是第 3 步的「提醒事项」（半截批，删掉重建）。
      - **重复每一项**，对象是 `时点`，内层循环里：
        - 两次 **获取词典值**（词典是「重复项目」，这时它指内层那一项），键分别是 `at`、`title`。
        - **从输入中获取日期**，输入 `at` 那一步的词典值（形如 `2027-01-23 10:00` 的文本）。
        - **添加新提醒事项**（iOS 18 起可能叫「创建提醒事项」），标题用 `title` 的词典值；点「显示更多」，列表「续保」，打开「提醒我」、时间设为上一步的「日期」，不开「紧急」，**不选「父提醒事项」**，备注 `备注`。
      - 内层循环结束后，**添加到变量** `已建`，值 `标题`。
   6. **否则**：**添加到变量** `已跳过`，值 `标题`。
10. 外层循环结束后：两次 **计数**（分别数 `已建`、`已跳过`），再 **显示通知**「续保：新建 N 批，跳过 M 批」，把两个计数插进去。嫌麻烦可先只写「续保导入完成」。

**「查找提醒事项」没有按「备注」过滤的选项时**：改成只按「列表是续保」查出全部，接 **重复每一项**，逐条 **获取提醒事项的详细信息**「备注」，再 **如果** 包含 `识别码` 判断。能用，只是慢；这一条要记进验证表，查重方案靠它。

**删除每次都要确认时**：iPhone「设置 → 快捷指令 → 高级」打开「允许删除而不确认」。律师手机上也得开，到时写进 `导入手机.md`。

## 试跑

把下面这段（案号是编的）粘进电脑版微信发给「文件传输助手」，手机上长按复制，点「续保导入」。这一步同时验证经微信复制后的长文本是否完整。

```json
{
 "format": 2,
 "list": "续保",
 "void": [],
 "batches": [
  {
   "id": "续保识别码：（测试）测01执保1号@2026-12-31",
   "title": "续保｜甲测试诉乙测试｜截止 2026-12-24",
   "notes": "保全案号：（测试）测01执保1号\n法院：测试法院\n届满日：2026-12-31（文书写明）\n申请截止日：2026-12-24（届满日前七日）\n财产：\n1. 测试存款（银行存款）\n续保识别码：（测试）测01执保1号@2026-12-31",
   "alerts": [
    {"at": "2026-10-10 10:00", "title": "续保｜甲测试诉乙测试｜截止 2026-12-24｜前 7 天"},
    {"at": "2026-10-10 17:00", "title": "续保｜甲测试诉乙测试｜截止 2026-12-24｜前 7 天"}
   ]
  }
 ]
}
```

| 试法 | 应该看到 |
| --- | --- |
| 第一次运行 | 「续保」列表多 2 条平铺的提醒（两个响铃点），标题带「前 7 天」、备注相同、时间都对，不挂在任何提醒下面；第一次会弹提醒事项授权 |
| 一个 `at` 改成几分钟后再导 | 到点来通知，通知上是响铃点的标题（带「前 7 天」） |
| 原样再导一次 | 不新建，通知说跳过 1 批 |
| 手动删掉其中 1 条再导（模拟上次没导完） | 剩下那 1 条被删掉，重建 2 条；通知说新建 1 批、其中重建 1 批 |
| 手动建一条标题「续保｜甲测试诉乙测试｜截止 2026-12-24」、备注只有识别码一行、不设时间的提醒，再导 | 当作旧版留下的半截批：删掉它，重建 2 条 |
| `"void": []` 改成 `["续保识别码：（测试）测01执保1号@2026-12-31"]` 再导 | 2 条都删掉、再建一套 |
| `"format": 2` 改成 `3` | 弹「请更新快捷指令」，什么都不建 |
| 复制一段普通文字再点 | 提示「剪贴板里不是导入文本」（生成件）或弹出相机（手搭件的扫码分支） |

上面每一项都要在一台 iOS 26.6 以上和一台 26.5 以下的 iPhone 上各走一遍。

## 分享

快捷指令详细信息（ⓘ）→ 分享 → 拷贝 iCloud 链接；在一台没装过的 iPhone 上点一遍，确认能装。

当前发布的链接（2026-10-12，平铺生成件，认格式号 2，签名件同在仓库 `dist/续保导入.shortcut`）：<https://www.icloud.com/shortcuts/50a09fab8650481d8b1386d25b6901ab>。2026-10-10 的子任务样式链接 <https://www.icloud.com/shortcuts/8954a1d50071420091b184b025a278d8> 停用，照它装的在 iOS 26.6 起报「不支持子任务」，律师要重装。格式号 1 的旧链接 <https://www.icloud.com/shortcuts/63139aa1630e4e98b3f912ffc40d20c4> 停用，照它装的快捷指令导入时会提示「请更新快捷指令」。重新生成发布后，同时改这里、`skills/xubao/导入手机.md`、根 `README.md` 与 `dist/` 四处。

## 真机验证记录

| 项 | 结果 |
| --- | --- |
| 「新建提醒事项」显示更多里能设哪些字段（列表、提醒时间、备注、URL、标签），能否设第二个时间或提前提醒 | 2026-10-09 生成件实测：列表（按导入文本里的列表名）、提醒时间、标题、备注都设上了；URL、标签、第二个时间未试 |
| 「查找提醒事项」能否按备注内容在指定列表里查到已有提醒 | 未直接验证：工具包参数表里提醒事项可过滤的属性没有备注，生成件改为按标题前缀找出、逐条读备注比对识别码；开发者测试后于 2026-10-09 发布 |
| 微信文件传输助手里长按复制的长文本是否完整，JSON 引号有没有被换成全角 | 2026-10-09 实测：完整，引号未变 |
| `YYYY-MM-DD HH:MM` 文本经「从输入中获取日期」能否转成正确时间 | 2026-10-09 实测：能。时间参数要写成「文本里插变量」，直接挂变量报「提供的提醒时间无效」 |
| 子提醒（父提醒事项）到点是否照常通知 | 2026-10-10 格式号 2 生成件在 iOS 26.5 实测：照常通知，通知上是子提醒的标题（带档位）。**2026-10-11 律师试用：iOS 26.6.1、26.6.2 上建第一个子提醒就报「账户 iCloud 不支持子任务」，父条留下、响铃点一个没建；26.5 两台正常。子任务样式已撤** |
| 勾掉父条是否一并勾掉子提醒；没勾掉的到点还响不响 | 2026-10-10 实测：勾掉父条，子提醒一并勾掉（子任务样式已撤，留作记录） |
| 作废重导时旧的续保提醒与子提醒是否删干净 | 2026-10-10 实测：void 带识别码重导，旧父条与子提醒都删掉，新建一套 |
| 平铺生成件：「匹配文本」数识别码次数、「计算」相减、「如果 大于 0」这三步在真机上是否成立 | 2026-10-12 实测：原样再导一次跳过，手动删一条再导重建，三步成立 |
| 平铺生成件在 iOS 26.6 以上是否整套跑通 | 2026-10-12 实测：26.6 与 26.5 各一台整套跑通 |
| 删除提醒事项能否不逐条确认 | 一次删除弹一次确认；「设置 → 快捷指令 → 高级」的「允许删除而不确认」可免，未逐项实测 |

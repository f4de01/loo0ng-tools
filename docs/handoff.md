# 交接：loo0ng-tools 起步与第一件 skill preservation-reminder

2026-10-08 在 loo0ng-skills 的开发会话里经一轮拷问定下，开发者逐题确认。本文是新仓第一个实现会话的输入；词汇见 `CONTEXT.md`，提醒基准的理由见 `docs/adr/0001`。

## 为什么另建仓

loo0ng-skills 是案件图工作台（破产先行，诉讼、执行等案件图随后导入），每件 skill 都要登进路由 `ask-loo0ng` 的两张表、词汇表围着图写、发版链重。保全提醒、OCR、格式转换排版这类不碰图的工具放进去，会把路由撑成工具目录、词汇打架、发版互相拖。所以工具另起本仓。边界：将来诉讼、执行案件图里的「续保申请书」节点与出件归 loo0ng-skills，提醒归本仓。

## 需求来源

律师申请财产保全后，被冻结、查封、扣押的财产有保全期限，期满前要向法院申请续行；律师事务繁杂，需要一个快速导入、不易失效的提醒。路径：agent（Codex 为主）里调 skill 读保全告知书、执行裁定书等 PDF，给出可粘贴的导入文本，到 iPhone 上由快捷指令导入提醒事项，定时响铃。

## preservation-reminder 的设计

**定位**：独立 skill，模型可自行调用（律师说「给这份告知书做续保提醒」之类即触发），不读写任何案件图。名字取律师的词「保全」，「续保」写进 description 的触发句。

**输入**：一份或多份 PDF（保全告知书、执行裁定书、协助执行回执等）。先抽文字层；抽不出或乱码的页渲染成图给模型看，不另上 OCR 依赖。

**分工**：
- 模型：读文书，一项财产写一行：案号、法院、申请人与被申请人、财产描述与类型、实施日、届满日、到期日来源（文书写明 / 推算）。
- 脚本（Python 标准库）：合并进保全底账、推算缺失的届满日、算全部提醒时点、拼导入文本。

**保全底账**：输入 PDF 同目录的 `保全期限.md`，脚本按固定列写成一张表，一项财产一行。律师可手改单元格（比如核对后改正推算日），下次运行脚本读回。重跑按「案号 + 财产」去重合并；续行后新届满日覆盖旧行，旧届满日留在备注。导入文本只含本次新增或变动的批，免得手机上重复。

**到期日来源**：文书写明的届满日优先（保全规定第十八条第二款要求法院书面告知明确的届满日，所以多数文书都有）。只有实施日的按下表推算并标「推算」，照常出提醒、标题带「推算待核」；两样都没有的不出提醒，问律师要日期。

| 财产类型 | 推算期限 | 依据 | 备注 |
|---|---|---|---|
| 银行存款 | 1 年 | 民诉法解释（2022 修正）第四百八十五条 | |
| 动产（含机动车） | 2 年 | 同上 | 机动车按动产是推断，无专门条文 |
| 不动产 | 3 年 | 同上 | |
| 其他财产权（含股权） | 3 年 | 同上 | 股权规定（法释〔2021〕20号）通篇无期限条 |
| 证券 | 2 年 | 法发〔2008〕4号第十二条 | 与解释「其他财产权 3 年」的关系实务有争议，回显时注明 |
| 证券交易结算资金 | 6 个月 | 同上 | 与解释「银行存款 1 年」的关系实务有争议，回显时注明 |

条文原文已于 court.gov.cn 核对：解释第四百八十五条 https://www.court.gov.cn/zixun/xiangqing/353651.html ；保全规定第十八条 https://www.court.gov.cn/fabu/xiangqing/30101.html （核的是 2016 年原文，2020 修正应未动此条，未逐字比对）；4号文 https://www.court.gov.cn/shenpan/xiangqing/717.html 。

**续保提醒**（基准见 ADR-0001）：
- 申请截止日 = 届满日减 7 日。两档：截止日前 30 天、前 7 天；每档 10:00、12:00、17:00 各一条（一条提醒只能挂一个时间），每批 6 条，进专门列表「续保」。
- 批：同一案号下届满日相同的财产合成一批，一份续保申请书覆盖一批。
- 标题：「续保｜申请人简称诉被申请人简称｜截止 YYYY-MM-DD」，推算的加「推算待核」。
- 备注：保全案号、法院、届满日、到期日来源、财产清单、识别码（案号 + 届满日）。
- 来晚了：已过的时点跳过；一档都不剩而截止日未到，立即建一条今天的并在对话里醒目警告；截止日已过不建，明说已过法定申请期限，请律师自行判断（如问法院可否依职权续行）。

**输出**：对话里先给一张人读的摘要表，再给一个 Markdown 代码块装导入文本（界面上点一下复制）。不写剪贴板、不另存文件；底账随时可重新导出。

**导入文本**：JSON，带格式版本号；快捷指令见版本不符即提示「请更新快捷指令」，不悄悄建错。

**到 iPhone**：
- Windows：代码块复制进电脑版微信发给文件传输助手，手机上长按复制，点快捷指令。
- Mac：复制后通用剪贴板已在 iPhone 上，直接点快捷指令。

**快捷指令**：开发者在自己的 iPhone 上照本仓的搭建步骤手工做一次，iCloud 链接写进 README，律师点一下装上（Windows 上程序生成的 `.shortcut` 未经 Apple 签名，iOS 15 起导入不了）。读剪贴板 JSON（「从输入中获取词典」）→ 逐批逐条（「重复每一项」）→ 先在「续保」列表按备注里的识别码查重，已有就跳过 → 「新建提醒事项」。一开始就同时认剪贴板与扫码两种输入，日后加二维码不用改它。

## 先在真机上验证（实现前或实现中）

1. iOS 26 上「新建提醒事项」（或 iOS 18 起的「创建提醒事项」）在「显示更多」里到底能设哪些字段：列表、提醒时间、备注、URL、标签。能否设第二个时间或提前提醒，目前没有任何来源说可以，按不能设计。
2. 快捷指令能否按备注内容在指定列表里查到已有提醒（查重靠它）。
3. 微信文件传输助手里长按复制的长文本是否完整，JSON 有没有被改动（比如引号被换成全角）。
4. Codex 在 Mac 上能否跑 `shortcuts run`（第二步才用）。

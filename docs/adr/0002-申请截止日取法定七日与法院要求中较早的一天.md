# 申请截止日取法定七日与法院要求中较早的一天

ADR-0001 把续保提醒的基准定为申请截止日，并按保全规定第十八条第一款取「届满日减 7 日」。第一次拿真件实测，就碰上一份财产保全告知书写着「到期前两周，向承办法官递交书面续保申请」：法院自己的要求比法定七日早一周。照旧按届满减 7 算，标题里的截止日比法院要的晚七天，第二档提醒正好落在法院要求的最后一天。我们决定：**申请截止日取「届满日前七日」与「届满日前法院要求的天数」中较早的一天**。法院要求由模型从文书里读出，写进财产行的「提前天数」（只填天数，如两周填 14）；没有这类话就空着，仍按法定七日。提醒时点、标题、备注一律按这个截止日算，ADR-0001 的两档三时点不变。

## 后果

- 识别码仍是「案号 + 届满日」，与提前天数无关：已经导进手机的提醒不用整批重导。某一批后来补上了提前天数，脚本把这一批列进作废、按新截止日重建。
- 「已过期限」只看法定截止日。过了法院要求的截止日而法定截止日未到，按紧急建一条当天的提醒，并说明法定截止日还没到，请律师立刻联系承办法官；不当作已过法定期限不建。
- 提前天数小于七按七算：法院不可能把法定期限往后放。同一件财产先后读到两种要求，取更早的。
- 保全底账多一列「提前天数」。之前写的底账没有这一列，照读，写回时补上。
